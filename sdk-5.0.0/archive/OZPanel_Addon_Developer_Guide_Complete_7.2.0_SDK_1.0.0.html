Từ addon Bash đầu tiên đến gói SDK có manifest, chữ ký, hook và rollback. Một tài liệu thống nhất với các giới hạn được đối chiếu rõ theo core 7.2.0.

Lộ trình khuyến nghị: chọn loại addon → đọc hợp đồng tích hợp → tạo addon mẫu → kiểm tra CLI/GUI → kiểm tra integrity/license → chuẩn bị phát hành.
Không tìm thấy nội dung phù hợp. Hãy thử từ khóa khác.

01 · Bắt đầu từ đúng mô hình

Tài liệu hợp nhất dành cho nhà phát triển addon OZPanel. Phần core được đối chiếu với mã nguồn oz_v7.2.0.sh; phần SDK dựa trên tài liệu SDK 1.0.0 được đính kèm.

Ranh giới quan trọng: các tệp được gửi trong cuộc trò chuyện là hai tài liệu HTML và mã core shell; chưa có mã nguồn SDK thực tế như ozsdk.py, lib/ozaddon.sh, lib/ozaddon.py và thư mục tests/. Vì vậy tài liệu dưới đây hợp nhất và cập nhật hướng dẫn, nhưng không tuyên bố đã sửa/chạy kiểm thử mã SDK chưa được cung cấp.

Để đọc đúng tài liệu: CORE ĐÃ ĐỐI CHIẾU nghĩa là hành vi nhìn thấy trong oz_v7.2.0.sh; SDK THEO TÀI LIỆU là giao diện SDK được mô tả trong file SDK guide; KHUYẾN NGHỊ là nguyên tắc phát hành an toàn, không phải tính năng tự động của core.

04 · Bắt đầu: addon legacy chạy được ngay

Cách nhanh nhất để thử

  1. Tải ví dụ an toàn ở bộ tài liệu: addon_demo_9001.sh.
  2. Kiểm cú pháp trên máy phát triển: bash -n addon_demo_9001.sh.
  3. Trên VPS thử nghiệm, sao lưu trước nếu đã có tệp addon mang ID này.
  4. Cài bản thử nghiệm ở thư mục addon và ghi metadata version bằng lệnh bên dưới.
  5. Mở [15] → [3] → nhập ID 9001. Hoặc kiểm menu chính sau khi nó được vẽ lại để xem shortcut 9101.
bash
bash -n examples/classic/addon_demo_9001.sh
sudo install -d -m 700 /etc/ozon/addons
sudo install -m 700 examples/classic/addon_demo_9001.sh /etc/ozon/addons/addon_9001.sh
printf '%s\n' '1.0.0' | sudo tee /etc/ozon/addons/addon_9001.version >/dev/null
sudo chmod 600 /etc/ozon/addons/addon_9001.version
# Sau đó mở /usr/bin/oz → [15] → [3] → 9001
ID 9001 chỉ là ví dụ phát triển. Cài thủ công chỉ phục vụ thử nghiệm, không đưa addon lên catalog cloud. Không chép đè ID đã được addon khác sử dụng.

Đối với SDK

bash
# Chạy trong thư mục SDK đã giải nén (cần có ozsdk.py thật)
python3 ozsdk.py --version
python3 ozsdk.py doctor
python3 ozsdk.py init ./my-addon --id 9001 --publisher your-studio
python3 ozsdk.py validate ./my-addon
python3 ozsdk.py pack ./my-addon --out ./my-addon/dist/demo.ozaddon
python3 ozsdk.py --root "$PWD/demo-panel" install ./my-addon/dist/demo.ozaddon --allow-unsigned
python3 ozsdk.py --root "$PWD/demo-panel" run 9001
python3 ozsdk.py --root "$PWD/demo-panel" health 9001
python3 ozsdk.py --root "$PWD/demo-panel" list

Các lệnh SDK phía trên theo tài liệu SDK 1.0.0 và giả định thư mục SDK chính thức có đủ ozsdk.py, thư viện và kiểm thử. Chỉ dùng --allow-unsigned cho gói dev không ký mà bạn chủ động chấp thuận; cờ này không bỏ qua yêu cầu chữ ký của publisher đã trust.

05 · Catalog Kho legacy: cấu trúc chính xác

CORE ĐÃ ĐỐI CHIẾU Core 7.2.0 đọc catalog tại https://api.l.lc/oz/api/client/addons/list, lưu cache ở /etc/ozon/store.list. Không có endpoint publisher/upload được xác nhận trong mã được cung cấp.

text
a_id|a_name|a_auth|a_org|a_ver|a_date|a_size|a_type|a_desc|a_url
TrườngÝ nghĩaQuy tắc

text
9001|OZ Demo|Your Studio|Your Company|1.0.0|2026-10-21|4 KB|Miễn phí|Addon demo để học hợp đồng legacy|https://downloads.example.net/oz/addon_9001-1.0.0.sh

Mã hiện tại dùng file tạm để nhận catalog, kiểm tra cấu trúc cơ bản rồi thay cache. Khi API lỗi, nếu cache cũ không rỗng và không phải trạng thái ERROR/EMPTY thì core giữ lại và tiếp tục dùng danh sách đã lưu.

06 · Đường dẫn và vòng đời addon legacy

Hạng mụcĐường dẫn / hợp đồng trong core 7.2.0
Thư mục addon/etc/ozon/addons/
Payload Bash/etc/ozon/addons/addon_ID.sh
Payload binary/etc/ozon/addons/addon_ID.bin
Version/etc/ozon/addons/addon_ID.version (quyền 600 được đặt khi tải qua CLI)
License raw legacy/etc/ozon/addons/license_ID.key (quyền 600 cố gắng áp dụng)
Dữ liệu riêng đề xuất/etc/ozon/addon-data/ID/ — addon tự tạo và tự quản lý
Log / registry addon nội bộ/etc/ozon/addons/.internal/records/, logs/, quarantine/

Khi chạy từ [15], core export OZON_ADDON_DIR, OZON_ROOT_DIR và OZON_LICENSE_FILE theo đúng ID. Nên dùng các biến này thay vì hard-code đường dẫn. Payload được chạy như tiến trình con; không source mã addon vào shell core, và không cần gọi lại menu OZPanel.

Vòng đời Kho legacy

  1. Install: hỏi xác nhận; nếu catalog ghi loại chứa Trả phí, hỏi key; tải vào tệp tạm, từ chối tệp rỗng, rồi thay payload và ghi version.
  2. Update: so version với catalog. Nếu bản legacy thiếu file version, mục cập nhật sẽ từ chối ghi đè để tránh rủi ro.
  3. Run: helper guarded ghi nhật ký; nếu có trust/receipt license addon đã cấu hình thì yêu cầu entitlement hợp lệ.
  4. Remove: xóa payload và metadata; không gọi uninstall hook và không dọn service/cron/database/vhost.
Điểm cần biết khi cập nhật: mã addon_download tải xong và kiểm tra tệp không rỗng, sau đó xóa bản .sh/.bin cũ trước khi mv tệp mới. Đây chưa phải transaction atomic có backup/rollback; không nên mô tả là giữ bản cũ trong mọi trường hợp thất bại.

07 · Mẫu Bash đầy đủ và quy ước GUI

Bộ ZIP kèm sẵn file addon_demo_9001.sh. Mẫu hiển thị thông tin ổ đĩa, lưu một ghi chú không nhạy cảm bằng file tạm, quyền dữ liệu riêng 700 và file 600. Không có tải mã mạng, eval hay thay cấu hình web server.

Hợp đồng giao diện

  • In từng lựa chọn trên một dòng: [1] Xem thông tin, [0] Quay lại.
  • Dùng read -r -p cho input; read -r -s -p khi cần nhập bí mật. Không echo, log hoặc truyền key qua argv.
  • OZ_GUI_FORM=1 cho biết prompt đang được cầu nối GUI hiển thị như biểu mẫu.
  • Với nano/vi/vim, dùng tên lệnh trong PATH hoặc biến EDITOR để GUI có thể chuyển hướng sang web editor. Đường dẫn tuyệt đối có thể bỏ qua shim.
  • Curses, top/htop, full-screen TUI, shell lồng nhau và chương trình cần TTY trực tiếp có thể cần Terminal nâng cao; phải thử CLI và GUI thực tế.
  • Đừng tự tạo file cấu hình giả hoặc cài dependency khi chỉ mở menu. Báo rõ file/service còn thiếu.
bash
if [[ "${OZ_GUI_FORM:-0}" == 1 ]]; then
  printf 'Đang chạy qua biểu mẫu GUI.\n'
fi

# Chỉ mở file cấu hình nếu file đã tồn tại.
if [[ -f "$OZON_ROOT_DIR/addon-data/9001/settings.conf" ]]; then
  nano "$OZON_ROOT_DIR/addon-data/9001/settings.conf"
fi

Addon CLI chạy với quyền của tiến trình panel (thường root). Thiết kế menu nên tách thao tác đọc khỏi thay đổi hệ thống; yêu cầu xác nhận trước khi ghi cấu hình, cài package, mở cổng, tạo service hoặc xóa dữ liệu.

08 · Luồng addon nội bộ [15] → [6]

Đây là luồng riêng, không đăng ký addon lên cloud catalog. Core cấp ID từ dải 900000–999999, tránh các ID đã thấy trong file addon, registry nội bộ và cache store.

SHA256Có thể cung cấp checksum 64 ký tự hex; nếu cung cấp và không khớp thì từ chối cài.

BinaryKiểm ELF header và architecture; kiểm tra machine x86_64/amd64 hoặc aarch64/arm64 theo môi trường.

Menu [7] đọc log. Log sự kiện là JSONL và được xoay vòng khoảng 2 MiB. Nếu bật thu thập stderr, tối đa một phần output được ghi log để hỗ trợ chẩn đoán; không bật mặc định cho luồng chứa secret.

Luồng nội bộ tăng cường kiểm tra tính toàn vẹn nhưng không phải sandbox. Addon vẫn có thể chạy bằng quyền quản trị. SHA256 do cùng một nguồn không đáng tin cung cấp không chứng minh publisher là ai; dùng checksum lấy qua kênh độc lập.

09 · OZPanel Addon SDK 1.0.0: mô hình và bố cục

SDK THEO TÀI LIỆU SDK mô tả một công cụ Python stdlib để tạo, kiểm tra, đóng gói và quản lý release addon; dựa trên tài liệu được gửi, không yêu cầu pip/Node/daemon riêng.

10 · Manifest, package và giới hạn artifact

Ví dụ dưới đây là template để tham khảo; SDK phải validate và tạo map checksum files khi pack. Chỉnh ID, publisher, min version, permission, entrypoint và đường dẫn hook đúng project thực tế.

json
{
  "schema": 1,
  "id": 9001,
  "publisher": "your-studio",
  "name": "My OZ Addon",

  • ID SDK theo tài liệu: 1–999999; publisher slug 2–48 ký tự; version hiện theo x.y.z, chưa nhận prerelease/build metadata.
  • Archive chỉ được chứa file khai báo và metadata; từ chối symlink/device, path tuyệt đối, ../, file trùng hoặc file ngoài manifest.
  • Giới hạn theo tài liệu SDK: 24 MiB nén, 64 MiB sau bung, 16 MiB/file và 2.000 payload file.
  • Bỏ qua dist/, .git/, __pycache__/; từ chối các tên/đường dẫn nhạy cảm như .env và private key dễ nhận diện.
  • architectures kiểm tra tính phù hợp, không tự chọn/tải binary đúng CPU thay cho publisher.
  • Để phát hành đa kiến trúc, build và kiểm thử từng artifact phù hợp; không đóng nhiều binary rồi trông chờ loader tự phát hiện.

11 · Ký, trust publisher và kiểm chứng chuỗi phân phối

bash
# Sinh key ở máy phát triển; private key tuyệt đối không phát hành
python3 ozsdk.py keygen --private ../sdk-keys/private.pem --public ../sdk-keys/public.pem

# Đóng gói archive có chữ ký
python3 ozsdk.py pack ./my-addon --out ./my-addon/dist/demo.ozaddon \
  --sign-key ../sdk-keys/private.pem

# Đăng ký public key nhận qua kênh tin cậy và kiểm tra gói
python3 ozsdk.py --root "$PWD/demo-panel" trust your-studio ../sdk-keys/public.pem
python3 ozsdk.py --root "$PWD/demo-panel" verify ./my-addon/dist/demo.ozaddon
python3 ozsdk.py --root "$PWD/demo-panel" install ./my-addon/dist/demo.ozaddon

# Nếu cần launcher tương thích kho legacy — hiểu rõ giới hạn bên dưới
python3 ozsdk.py pack ./my-addon --out ./my-addon/dist/addon_9001.sh \
  --sign-key ../sdk-keys/private.pem --legacy

Theo tài liệu SDK, chữ ký Ed25519 bao phủ canonical UTF-8 manifest (sorted keys, compact); manifest chứa checksum các file payload. Archive dùng timestamp cố định để hỗ trợ build tái lập. Lệnh fetch yêu cầu HTTPS, checksum SHA256, giới hạn dung lượng và không theo redirect.

  1. Giữ private key ngoài repo và ngoài artifact.
  2. Phân phối public key/fingerprint qua một kênh độc lập với URL tải gói.
  3. Kiểm tra checksum và chữ ký trước khi cài. Không coi TLS đơn lẻ là bằng chứng publisher.
  4. Đổi trust key sẽ làm các release ký bằng key cũ không còn verify; SDK 1.0.0 theo tài liệu chưa có key-ID/multi-key rotation, vì vậy cần kế hoạch ký lại trước.
Không trộn trust boundary: SDK verify/install chỉ bảo vệ luồng được thực thi qua SDK và trust store đúng. Core [15] legacy không giải nén/kiểm tra toàn bộ archive .ozaddon. Launcher --legacy chạy qua core không có nghĩa core đã cưỡng chế xác minh Ed25519 trước khi launcher được thực thi. Nếu cần cưỡng chế ở mọi đường cài đặt, phải tích hợp verifier vào core hoặc chỉ dùng đường SDK đáng tin cậy.

bash

Nếu hook thất bại, SDK gọi hook rollback best-effort và giữ bản active trước; lỗi commit cố gắng khôi phục launcher/version/state. Đây không phải giao dịch phân tán cho database, DNS, vhost hoặc service OS. Hook của addon vẫn phải sao lưu, validate, áp dụng và phục hồi các thay đổi đó.

Gỡ addon SDK bằng [15] → [4] của core legacy không gọi uninstall hook SDK. Dùng lệnh ozsdk.py remove trong đúng runtime SDK để chạy cleanup. Các ví dụ gỡ là lựa chọn thay thế, không chạy nối tiếp một cách máy móc.

16 · Dữ liệu, service, web server và cleanup

  • Tách menu khỏi tác vụ cài đặt: không build, quét toàn ổ đĩa hay cài dependency nặng mỗi lần mở addon.
  • Định nghĩa install/upgrade/health/uninstall rõ ràng; các thao tác cần idempotent để có thể chạy lại an toàn.
  • Service dài hạn nên dùng systemd unit riêng, user hệ thống riêng nếu khả thi, giới hạn CPU/RAM và log rotation.
  • Với multi Nginx/OpenLiteSpeed/Apache, hãy dò engine/vhost thực tế; backup file, validate cú pháp và reload đúng dịch vụ.
  • Không tự ghi đè vhost mặc định, SSL, SSH port hoặc firewall chung. Hiển thị rõ domain/path/port sẽ thay đổi và yêu cầu xác nhận.
  • Migration DB/config cần version schema, backup trước khi thay đổi, health check sau khi triển khai và cách rollback.
  • Quy trình remove cần cho quản trị viên chọn giữ/xóa dữ liệu; dừng service/cron do addon tạo trước khi gỡ payload.
bash
# Quy trình gợi ý bên trong hook do addon tự triển khai:
# 1. Kiểm tra quyền, dependency và quyền sở hữu file mục tiêu.
# 2. Backup cấu hình/dữ liệu vào vị trí chỉ root truy cập.
# 3. Viết file tạm; kiểm tra cú pháp bằng công cụ của dịch vụ.
# 4. Chuyển file vào vị trí; reload đúng service.
# 5. Health check có timeout; phục hồi backup nếu thất bại.
# 6. Ghi kết quả, tuyệt đối không log password/token/license.

Core không tự tạo service, proxy, firewall, dữ liệu hay uninstall hook cho addon legacy. SDK rollback chỉ quản lý release/state của runtime; việc khôi phục dịch vụ/dữ liệu do hook addon chịu trách nhiệm.

17 · Quy trình phát hành và đưa addon lên kho

  1. Cấp ID: yêu cầu chủ catalog quản lý ID. Không dùng ID ví dụ 9001 cho phát hành thương mại.
  2. Đóng gói bất biến: đưa version vào tên artifact, chốt nguồn, không thay bytes sau khi xuất checksum/chữ ký.
  3. Kiểm thử: sạch, nâng từ version trước, lỗi tải, rollback, kiến trúc CPU, CLI/GUI, gỡ và cài lại.
  4. Metadata: mô tả chức năng, tác giả, tổ chức, version, ngày, kích thước, loại license, dependency, hệ điều hành/CPU, quyền, dữ liệu thu thập và hỗ trợ.
  5. Kiểm chứng phát hành: công bố SHA256 riêng; với SDK, ký manifest bằng Ed25519 và quản lý trust publisher.
  6. Phân phối: tài liệu mã 7.2.0 xác nhận endpoint đọc catalog, không xác nhận portal hoặc API upload cho publisher. Gửi gói qua quy trình do quản trị viên Kho chỉ định.
  7. Refresh: cập nhật catalog phía máy chủ rồi chạy [15] → [5] trên VPS thử nghiệm.

Điểm được cập nhật theo mã core 7.2.0

  • Đổi URL catalog sang https://api.l.lc/oz/api/client/addons/list.
  • Bổ sung các lựa chọn [6] addon nội bộ, [7] log và [8] restore/cách ly.
  • Mô tả đúng luồng nội bộ: cấp ID 900000–999999, tối đa 32 MiB, SHA256 tùy chọn, kiểm tra Bash/ELF, registry/log/quarantine và kiểm hash khi chạy nếu có metadata.
  • Cập nhật đường dẫn helper/metadata theo /etc/ozon/addons và môi trường mà core export cho addon.
  • Sửa nội dung lỗi thời rằng luồng tải legacy luôn giữ payload cũ: mã hiện xóa payload cũ trước bước mv cuối nên chưa có rollback nguyên tử.
  • Thêm các giới hạn API thực tế: cài/update API lưu trực tiếp file Bash, không giống CLI; gỡ API chưa xóa version metadata; route catalog có thể có envelope không thống nhất tùy nhánh.
  • Tách riêng license raw legacy, entitlement addon của core và license offline riêng của SDK.

Những điều không tuyên bố

  • Không tuyên bố đã sửa mã oz_v7.2.0.sh hoặc cài SDK vào control panel.
  • Không tuyên bố core legacy đã bắt buộc verify Ed25519/SHA256 trên mọi đường cài đặt.
  • Không tuyên bố đã chạy ozsdk.py, unit tests của SDK, compile Go, kiểm browser hoặc triển khai trên VPS; source SDK không được gửi kèm.
  • Không khẳng định endpoint publisher/upload của chợ tồn tại; mã được kiểm tra chỉ xác nhận endpoint đọc catalog và các adapter nêu ở trên.
